# 默认打开方式 (文件关联) 架构

NeoRunST 的"用 xxx 程序打开 xxx 文件"机制, 模型参照 Windows:
**程序注册 + 扩展名关联**, 全部存在注册表 default.rreg 里,
文件管理器双击时查询注册表决定行为。

## 注册表布局

```
/Application/<软件名>/            一个已注册的应用
    DisplayName   REG_SZ_UTF8     列表里显示的名称 (如 "BMP 查看器")
    Desc          REG_SZ_UTF8     一句话描述
    Cmd           REG_SZ_UTF8     启动命令模板, %1 = 被打开文件路径
/FileAssociations/<.扩展名>/      一个已注册的文件类型 (挂任意应用名下)
    Desc          REG_SZ_UTF8     类型描述 (如 "BMP 位图文件")
    Verb          REG_SZ_UTF8     动作名 (如 "open", 预留)
```

要点:

- 关联键 `.ext` 挂在**应用自己的** `FileAssociations` 子键下 (一个类型
  可以被多个应用各自声明), 查询时扫描所有 `/Application/*/FileAssociations`
- `Cmd` 第一段是 NEP 程序路径 (引号包裹或到第一个空格), 其余按 `%1`
  字面替换成目标文件完整路径, 生成 GetCommandLine 语义的命令行原文
- 程序内用 `nep_get_args(&argc)` 取 `argv[1]` = 被打开文件路径

## 双击分发流程 (filemgr)

| 扩展名 | 行为 |
|--------|------|
| `.nep` | 直接启动 (可执行文件本身) |
| 无任何注册关联 | 弹"打开方式"窗口 (type 17) |
| 弹窗内无候选 | 提示 `'<文件名>' 没有已注册的打开方式` |

"打开方式"窗口列出所有声明了该扩展名的应用 (DisplayName + Desc),
选中后点 **仅一次** 启动 (**始终** 按钮预留, 置灰)。

## 内置强绑定的查看器

`.bmp` / `.ttf` / `.wav` / `.rreg` 仍由内核内置查看器直接打开
(不走注册表)。注册表关联面向内核不认识的任意扩展名与第三方 NEP 程序。

> 内置 BMP 查看器已迁移为系统软件 `app/bmpview.nep` (NEP 程序,
> 经 syscalls 29/30 直绘), 注册关联是它的推荐入口。

## 注册示例: sysappinit

系统软件安装后, 在终端执行隐藏命令 `sysappinit` (help 中不显示),
向 default hive (default.rreg) 写入 BMP 查看器的注册项
(打开方式查询走程序 API = default hive; 幂等, 重复执行结果一致):

```
/Application/in_app_bmp_view
    DisplayName = "BMP 查看器"
    Desc        = "NeoRunST 系统图像查看器"
    Cmd         = "ZZ://runst/app/bmpview.nep %1"
/Application/in_app_bmp_view/FileAssociations/.bmp
    Desc        = "BMP 位图文件"
    Verb        = "open"
```

之后在文件管理器双击 `.bmp` → 弹"打开方式" → 选"BMP 查看器" →
仅一次 → bmpview.nep 以 `bmpview.nep <bmp完整路径>` 命令行启动。

## 第三方程序接入

1. 写一个 NEP 程序, `nep_main` 里 `nep_get_args` 取 `argv[1]` 打开文件
2. 拷到任意盘 (如 `ZZ://runst/app/`)
3. 用 shell 的 `reg` 命令 (或注册表编辑器) 写入上面两段注册项
   (`reg_set` 路径逐级自动建键)

参考实现: `sysapp/bmpview.c` (SDK: `dev/tools/nep.h`)。
